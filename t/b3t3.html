1. Lenguajes de bases de datos. Estándar ANSI/SQL

  • SQL (Structured Query Language): lenguaje estándar de las BD relacionales; declarativo. Desarrollado por IBM en los 70 (proyecto System R, nombre SEQUEL); normalizado por ANSI (1986) e ISO (1987).
  • Objetivos del estándar: lenguaje común y portable, fijar sintaxis y semántica, interoperabilidad entre SGBD, consultas/manipulación/definición/control de acceso de forma declarativa.
VersiónAñoNovedades

SQL-891989Mejoras menores
SQL-921992Muy extendido: JOIN, CHECK, IN, UNION, subconsultas
SQL:19991999Procedures y triggers
SQL:20032003XML, tipos autoincrementales (IDENTITY)
SQL:20112011Consultas temporales (PERIOD, SYSTEM_TIME)
SQL:20162016JSON, funciones analíticas y agregadas

EXAMEN

GROUP BY

Agrupa filas con valores idénticos en una o varias columnas para aplicar funciones de agregación (SUM, AVG, COUNT…). Ej.: SELECT DepartamentoID, COUNT(*) FROM Empleados GROUP BY DepartamentoID;

  • HAVING: filtra después de GROUP BY, con condiciones sobre agregaciones (imposible con WHERE). Ej.: HAVING COUNT(*) > 10.

3. Lenguajes de BD

3.1 DDL (afecta al esquema, no a los datos)

InstrucciónFunción
CREATECrea tablas, vistas, índices, esquemas, usuarios, procedimientos y funciones. CREATE TABLE nombre (columna tipo [restricciones], …);
ALTERModifica la estructura: añadir columnas (ADD), cambiar tipo (MODIFY / ALTER COLUMN), eliminar (DROP COLUMN), renombrar (RENAME COLUMN / RENAME TO), añadir o quitar restricciones
DROPElimina el objeto completo (tabla, vista, índice…), estructura y datos, permanentemente (solo recuperable con backup)
TRUNCATEVacía la tabla manteniendo su definición
IMPORTANTE

DROP

Algunos SGBD admiten IF EXISTS (DROP TABLE IF EXISTS Empleados;) para evitar errores. Si hay claves foráneas que dependen de la tabla, el SGBD puede impedir el borrado salvo que se eliminen antes esas relaciones o se use CASCADE.

TRUNCATEDELETE
WHERENo permite (elimina todo)Sí permite
VelocidadMás rápida (opera a nivel de páginas)Más lenta (registra cada fila)
Triggers y logNo activa triggers ni registra fila a filaPuede activar triggers
TransacciónPuede deshacerse dentro de una transacción

3.2 DML (datos, sin alterar estructura)

EXAMEN

INSERT

Añade nuevas filas a una tabla existente; se puede indicar el valor de todas o algunas columnas. INSERT INTO tabla (c1, c2) VALUES (v1, v2); INSERT … SELECT inserta los resultados de una consulta (mismo nº y tipo de columnas).

  • UPDATE: UPDATE tabla SET col = valor [, …] WHERE condición; — solo una tabla por instrucción; el valor puede ser constante, expresión o subconsulta. Sin WHERE se modifican todas las filas (peligroso).
EXAMEN

DELETE

Elimina filas que cumplan una condición. Más flexible que TRUNCATE (permite WHERE). Sin WHERE borra todas las filas (como TRUNCATE, pero más lento y registrando cada eliminación); puede activar triggers; puede deshacerse en una transacción.

3.3 DCL

  • GRANT privilegios ON objeto TO usuario: concede permisos (SELECT, INSERT, UPDATE, DELETE, ALL).
EXAMEN

REVOKE

Retira permisos previamente otorgados a un usuario o rol sobre un objeto. REVOKE privilegios ON objeto FROM usuario;

3.4 OQL (Object Query Language)

  • Para BD orientadas a objetos; parte del estándar ODMG; inspirado en SQL (SELECT, FROM, WHERE, GROUP BY, ORDER BY) pero con clases, objetos, herencia, colecciones y navegación por referencias (e.departamento.nombre). Usado con ObjectStore, Versant, C++ y Java. Hoy residual frente a JPQL, HQL (Hibernate), LINQ.

4. Procedimientos almacenados

  • Bloques de código SQL almacenados y ejecutados en el servidor: encapsulan lógica de negocio, automatizan tareas, reutilizan operaciones y mejoran rendimiento.
  • MySQL: DELIMITER // CREATE PROCEDURE Nombre() BEGIN … END // DELIMITER ; · SQL Server: CREATE PROCEDURE Nombre AS BEGIN … END;
ParámetroDescripción
INEntrada: el procedimiento recibe un valor
OUTSalida: devuelve un valor al llamante
INOUTMixto: entrada y salida (MySQL)
EXAMEN

Parámetros OUT

Se utilizan para devolver información desde el procedimiento al llamante; útiles para cálculos, totales o consultas individuales. MySQL: OUT salario DECIMAL(10,2) con SELECT Salario INTO salario…. SQL Server: @salario DECIMAL(10,2) OUTPUT.

5. Eventos y disparadores (triggers)

  • Trigger: bloque SQL que se ejecuta automáticamente ante un evento (INSERT, UPDATE o DELETE) sobre una tabla; a diferencia de los procedimientos, no se llama manualmente. En MySQL, un evento también puede ser una tarea programada en el tiempo.
  • Sintaxis: CREATE TRIGGER nombre {BEFORE | AFTER} {INSERT | UPDATE [OF columna] | DELETE} ON tabla [FOR EACH ROW] [WHEN (condición)] BEGIN … END;
ElementoDescripción
OF columnaLimita un UPDATE a una columna
FOR EACH ROWUna vez por cada fila afectada
WHEN (condición)Solo si se cumple
TipoMomentoUso
BEFOREAntes de la operaciónValidar o modificar datos antes de insertarlos
AFTERDespués de la operaciónRegistrar lo ocurrido
PseudoregistroCuándoContiene
NEW.columnaINSERT, UPDATEValor nuevo
OLD.columnaUPDATE, DELETEValor antiguo (antes de modificar)
  • En INSERT no existe OLD; en DELETE no existe NEW.
  • Usos: auditoría (AFTER UPDATE → LogCambios), validación (BEFORE INSERT → error si NEW.Valor < 0), automatización (actualizar campos derivados o sincronizar tablas).

6. Transacciones y niveles de aislamiento

  • Transacción: unidad lógica de trabajo que se ejecuta completa o no se ejecuta; propiedades ACID.
SentenciaDescripción
BEGIN / START TRANSACTIONInicia la transacción
COMMITConfirma y guarda los cambios
ROLLBACKCancela y revierte los cambios desde el último BEGIN
SAVEPOINT nombrePunto de recuperación intermedio
ROLLBACK TO nombreDeshace parcialmente hasta el SAVEPOINT
RELEASE SAVEPOINTLibera el punto (PostgreSQL, Oracle)
