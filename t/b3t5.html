1. Introducción: plataformas empresariales

  • Plataforma empresarial: conjunto estructurado de tecnologías, herramientas, lenguajes y componentes para construir, desplegar y ejecutar aplicaciones robustas, escalables y mantenibles en entornos corporativos. Soportan muchos usuarios y transacciones, separación en capas (presentación, negocio, persistencia), seguridad, transaccionalidad, concurrencia, escalabilidad e interoperabilidad (servicios web).

3.3 Compilación

  • Se compila a bytecode (formato intermedio) que ejecuta la JVM, no a código máquina directamente.
FaseDescripción
1. CompilaciónSe crean los archivos con bytecode, independiente de la plataforma
2. EmpaquetadoCon Maven, Gradle o Ant: .jar (bibliotecas), .war (aplicaciones web), .ear (empresariales: módulos web y EJB)
3. DespliegueEl .war/.ear se despliega en un servidor Jakarta EE (GlassFish, Payara, WildFly); el contenedor gestiona el ciclo de vida de los componentes
4. Ejecución JITLa JVM convierte el bytecode a código máquina en ejecución
EXAMEN

Compilador JIT

La JVM no ejecuta directamente el bytecode, sino que lo convierte a código máquina en tiempo de ejecución mediante un compilador JIT (Just-In-Time).

3.4 Contenedores

  • El servidor de aplicaciones proporciona contenedores que gestionan automáticamente ciclo de vida, seguridad, inyección de dependencias y concurrencia.
ContenedorEjecuta
WebServlets, JSP, JSF; peticiones HTTP
EJBComponentes de negocio (Enterprise JavaBeans): transacciones, seguridad, concurrencia. Beans: Session Beans (stateless, stateful, singleton) y Message-Driven Beans (MDB)
PersistenciaEntidades JPA y conexiones a la BD
IMPORTANTE

Contenedor web vs contenedor EJB

Mientras que el contenedor web se centra en la interfaz de usuario y el protocolo HTTP, el contenedor EJB se orienta a la lógica empresarial, servicios internos, transacciones y comunicación entre componentes.

3.5 Servlets

  • Componente Java que se ejecuta en el servidor y genera contenido dinámico (HTML, XML, JSON) en respuesta a peticiones HTTP; vive en un contenedor web (Tomcat, Jetty, GlassFish). Funciones: procesar GET, POST, PUT, DELETE, gestionar sesiones, actuar como controlador MVC, redirigir.
Fase del ciclo de vidaMétodo
1. Carga de la clase
2. Instanciación
3. Inicialización (una sola vez)init()
4. Atención a peticiones (cada petición)service() → doGet(), doPost()…
5. Destrucción (una sola vez)destroy()

3.6 Enterprise JavaBeans (EJB)

  • Especificación para componentes de negocio en el servidor, dentro del contenedor EJB.
Tipo de EJBCaracterística
Session Bean StatelessSin estado; operaciones independientes y cortas
Session Bean StatefulMantiene estado del cliente (carrito de compra)
Session Bean SingletonUna única instancia compartida (configuración global)
Message-Driven Bean (MDB)Procesa mensajes asíncronos (JMS)
IMPORTANTE

Paquete de EJB

Las clases e interfaces EJB estaban tradicionalmente en el paquete javax.ejb (Java EE). En Jakarta EE, tras el cambio a la Eclipse Foundation, pasó a jakarta.ejb.

3.8 Persistencia

TecnologíaDescripción
JDBCAPI básica de acceso a BD relacionales con SQL: conexión mediante driver, ejecuta SELECT/INSERT/UPDATE/DELETE, resultados con ResultSet
JPAPersistencia con ORM (ver abajo)
EXAMEN

JPA

Especificación estándar de Jakarta EE para la persistencia de objetos Java en bases de datos relacionales usando el patrón ORM (Object-Relational Mapping).

  • Tablas ↔ clases, filas ↔ objetos; anotaciones @Entity, @Id, @OneToMany; consultas con JPQL (orientado a objetos).

3.9 Transacciones y conexión a BD

  • Transacción: unidad de trabajo ACID (Atómica, Consistente, Aislada, Durable). Si falla una parte, se deshace todo. En Jakarta EE: JTA, de forma declarativa o programática.
  • Conexión: se usan pools de conexiones (evitan abrir/cerrar repetidamente). En Jakarta EE: DataSource JNDI gestionado por el servidor; @PersistenceContext inyecta un EntityManager; el servidor gestiona el pool.

3.10 Seguridad: JAAS

  • Java Authentication and Authorization Service: API estándar de autenticación y autorización. Módulos de autenticación (usuario/contraseña, certificados); backends LDAP, BD, servicios externos; permisos mediante ficheros .policy o políticas declarativas.

4.3 Persistencia: ADO.NET y Entity Framework

EXAMEN

ADO.NET

Conjunto de clases de .NET para acceder y manipular datos de diversas fuentes (BD relacionales, XML). Acceso de bajo nivel y control total sobre las operaciones.

ClaseFunción
SqlConnectionConexión con SQL Server
SqlCommandEjecuta comandos SQL o procedimientos almacenados
SqlDataReaderLectura rápida, hacia adelante (streaming)
DataSetContenedor en memoria de varias DataTable; funciona desconectado
DataAdapterPuente entre BD y DataSet; sincroniza cambios
EXAMEN

Entity Framework

ORM oficial de .NET: permite trabajar con objetos de dominio sin escribir SQL manualmente para la mayoría de operaciones.

  • Menos código; gestiona conexión y conversión objeto↔tabla; define relaciones y restricciones con clases y atributos; CRUD con pocas líneas; soporta LINQ (consultas con sintaxis C#).
  • POCO (Plain Old CLR Object): objeto C# simple, que no hereda de clases específicas del framework ni lo requiere. Deriva de POJO (Java). Solo propiedades públicas get/set (puede tener métodos, eventos, delegados); sin anotaciones ni dependencias de EF o ASP.NET. EF los detecta por convención o configuración.

4.4 Seguridad: ASP.NET Identity

  • Gestión de usuarios y roles: registro, autenticación, contraseñas seguras, validación de email, 2FA; almacenamiento en BD SQL personalizable.

CLR

Common Language Runtime: motor de ejecución del framework .NET; ejecuta el código compilado a CIL (Common Intermediate Language) y ofrece un entorno seguro, gestionado y eficiente.

  • Todos los lenguajes .NET compilan a CIL (independiente de SO y procesador); el CLR hace compilación JIT a código nativo, gestiona memoria y recolector de basura (GC), hilos, seguridad y excepciones, y aísla del hardware.

4.6 Gestión de paquetes

EXAMEN

NuGet

Gestor de paquetes oficial de .NET: añade bibliotecas de terceros mediante comandos de consola; simplifica dependencias, actualizaciones y compatibilidad. Instalación CLI: dotnet add package <Nombre> (ej. dotnet add package iText); añade la referencia al .csproj y descarga desde nuget.org.
