2. Software de base

  • Programas que permiten al SO interactuar con el hardware y preparan el entorno para el resto del software: cargadores, SO, drivers, compiladores, interfaces de usuario, BIOS, gestores de arranque.
ComponenteDescripción
Cargador (loader)Carga en memoria un programa ejecutable; puede ser parte del SO (dynamic linker en Linux)
CompiladorTransforma código fuente de alto nivel en código máquina o bytecode. Fases: análisis léxico y sintáctico, optimización, generación de código objeto/ejecutable. Tradicionales (GCC) y JIT (Java, .NET: compilan en ejecución)
Entorno de escritorioInterfaz gráfica: gestor de ventanas, iconos, menús, widgets, explorador. GNOME, KDE Plasma, XFCE (Linux), Windows
BIOSFirmware en un chip de la placa base; lo primero que se ejecuta: POST (Power-On Self Test), inicializa teclado/pantalla/discos, busca dispositivo de arranque (disco, USB, red) y le cede el control; configuración básica. Sustituida por UEFI (más funciones, discos grandes, arranque seguro)
BootloaderToma el control tras BIOS/UEFI: carga el kernel y le transfiere el control. GRUB, LILO, Windows Boot Manager (bootmgr.exe)

Interfaces de usuario

CLI (Command Line Interface): comandos de texto; flexibilidad, rapidez y automatización (scripts); Bash, PowerShell, CMD. GUI (Graphical User Interface): elementos visuales; intuitiva (Windows, escritorios Linux). NUI (Natural User Interface): gestos, voz; dispositivos táctiles, asistentes virtuales.

  • Hipervisores (monitores de máquina virtual): ejecutan varios SO simultáneamente en una máquina física, cada uno virtualizado; consolidación de servidores, entornos de prueba y aislamiento.
Tipo 1 (bare-metal)Tipo 2 (hosted)
EjecuciónDirectamente sobre el hardware; no requiere SO anfitriónComo aplicación sobre un SO ya instalado
VentajasAlto rendimiento, eficiencia, mejor aislamiento y seguridadFácil instalación y uso; pruebas o uso personal
EjemplosVMware ESXi, Microsoft Hyper-V, Xen, KVMVirtualBox, VMware Workstation, Parallels Desktop

3. Gestión de usuarios y permisos

  • Cuenta de usuario: información que identifica a una persona, sistema o servicio; identidad única, vinculada a perfiles y privilegios (roles): qué recursos usa, qué acciones realiza y cuándo y cómo accede.
Buena prácticaIdea
Control de contraseñasCaducidad, complejidad mínima, bloqueo tras intentos fallidos (fuerza bruta)
Limitaciones de usoHorarios, sesión en un único dispositivo, menor privilegio
Seguimiento y auditoríaLogs de acciones, accesos, intentos fallidos, cambios
Ciclo de vidaDesactivar cuentas inactivas o de empleados que ya no pertenecen
  • Grupos (roles): agrupan cuentas con permisos comunes (en Windows, el grupo Administradores tiene acceso total). Perfiles: configuración personalizada de cada cuenta; locales o móviles (en dominio). Control de acceso: ACLs, permisos y privilegios, según identidad y grupo.

3.3 Permisos Unix/Linux: rwx

EXAMEN

Permisos rwx

PermisoEn archivosEn directorios
r (read)Leer el contenidoVer el contenido (listar)
w (write)Modificar el archivoCrear, renombrar o borrar archivos dentro
x (exec)Ejecutar (script o binario)Acceder al contenido (entrar con cd)

Se aplican por separado a tres grupos: usuario (user, propietario), grupo (group) y otros (others). ls -l muestra los permisos; p. ej. rwx = propietario, r-x = grupo (lee y ejecuta, no escribe), --x = otros (solo ejecutan).

EXAMEN

Notación octal

Cada grupo de 3 letras se codifica en octal (los 1 binarios marcan el permiso).

OctalBinarioPermisos
0000---
1001--x
2010-w-
3011-wx
4100r--
5101r-x
6110rw-
7111rwx
EXAMEN

Comando chmod

Modifica los permisos. Sintaxis: chmod [opciones] permisos archivo. Modo simbólico: chmod u+x archivo (añade ejecución al usuario), chmod g-w archivo (quita escritura al grupo), chmod o=r archivo (deja solo lectura para otros). Modo numérico: chmod 644 fichero.txt → lectura y escritura al propietario, solo lectura al grupo y a otros.

Fundamentales para los SLA y la continuidad de negocio.

  • Tareas periódicas: limpieza (temporales, logs), revisión de registros, actualización de software, monitorización de CPU/memoria/disco/red, copias de seguridad (verificar y probar la recuperación), control de usuarios (cuentas inactivas, permisos).
  • Gestión de incidentes: plataformas ITSM (IT Service Management) o ticketing, para los CAU (Centros de Atención de Usuarios): seguimiento, tiempos de respuesta, base de conocimiento, escalado. El ticket recoge la información del incidente y todas las acciones de los técnicos.

6. Reparación del sistema operativo

EXAMEN

Herramientas de diagnóstico y recuperación

Utilidades para detectar y corregir problemas sin reinstalar.

Windows: chkdsk (errores del sistema de archivos) · SFC (System File Checker: verifica y repara archivos del sistema) · DISM (Deployment Image Servicing and Management: repara imágenes del sistema y entornos de recuperación) · herramientas gráficas (diagnóstico de memoria, solucionadores).

Linux: fsck (comprueba y repara sistemas de archivos) · dmesg (mensajes del kernel; fallos de hardware o arranque) · Live USB + chroot (reparar particiones, reinstalar GRUB, restaurar configuraciones).

Modo de arranqueDescripción
Modo seguro (Safe Mode)Windows; mínimo de controladores y servicios; desinstalar software problemático, diagnóstico
Modo recuperaciónWindows y Linux; restauración y acceso a la línea de comandos
Live USB / Live CDEjecuta el SO sin instalar nada; acceder a discos, copiar archivos, reparar particiones, reinstalar el gestor de arranque o el sistema
ReinstalaciónDescripción
Conservando archivos (recuperación)Sin borrar documentos personales; restaura archivos del sistema
CompletaFormatea la unidad; requiere copia previa de datos, drivers y aplicaciones
  • Siempre: copias previas, medios de instalación (ISO, USB) y documentación de la configuración original.

7. Buenas prácticas de administración

  • Registro de cambios (change log): constancia de instalaciones, actualizaciones y cambios de configuración; facilita incidencias y trazabilidad en entornos auditables.
MonitorizaciónDescripción
NagiosMuy extendida: servicios, servidores, redes y aplicaciones
ZabbixRecogida de datos, alertas y paneles
Prometheus + GrafanaMonitorización y visualización moderna en tiempo real
CactiMonitorización de red con gráficos RRD
  • Genera alarmas automáticas cuando los indicadores son anómalos.
  • Seguridad en la administración: cuentas separadas para administración y uso personal · menor privilegio · MFA · cifrado de comunicaciones remotas (SSH, VPN) · control de sesiones y desconexión por inactividad. La mayoría de ataques utilizan al usuario interno.
EXAMEN

MDM y EMM

MDM (Mobile Device Management): gestiona dispositivos móviles (teléfonos, tablets, portátiles): aplicar políticas de seguridad, configurar remotamente, localizar y borrar dispositivos perdidos o robados. EMM (Enterprise Mobility Management): enfoque más amplio que incluye MDM + MAM (Mobile Application Management: apps permitidas) + MIM (Mobile Information Management: apps que acceden a datos corporativos).

  • Herramientas MDM/EMM: Microsoft Intune, VMware Workspace ONE, AirWatch, IBM MaaS360, Jamf (dispositivos Apple), Kaspersky EMM.
EXAMEN

Modelos de gestión de dispositivos

ModeloSignificadoDescripción
BYODBring Your Own DeviceEl empleado usa su propio dispositivo; flexible, pero con riesgos de seguridad y privacidad
CYODChoose Your Own DeviceEl empleado elige de una lista aprobada por la organización; control y soporte de la empresa
COPECorporate Owned, Personally EnabledDe la empresa, pero el empleado puede usarlo también para fines personales; equilibrado
COBOCorporate Owned, Business OnlyDe la empresa y solo uso laboral; el más restrictivo (administración pública, sanidad, fuerzas de seguridad)
  • BYOD y CYOD: políticas de control parciales, sin invadir la privacidad. COPE y COBO: control total (borrado remoto, configuración completa, control de aplicaciones).
